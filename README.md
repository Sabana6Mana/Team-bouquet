# MATCHPOINT

> 동네에서 같이 운동할 사람을 못 구해 운동을 포기하는 사람이,
> 지도에서 실력이 맞는 상대와 즉시 매칭되고 근처 체육관 빈 시간까지 한 번에 잡는 앱.

핵심 컨셉은 **운동의 게임화**입니다. 포켓몬 GO처럼 지도를 탐색하고, 체육관마다
ELO 리더보드와 최근 경기 전광판이 붙어 있으며, 경기 결과가 레이팅과 티어에 반영됩니다.

## 백엔드 MVP

Supabase 환경변수가 없으면 기존 NPC 데모로, 환경변수가 있으면 실제 사용자 백엔드로
동작합니다. 백엔드 모드에는 로그인, 프로필, 3km·ELO 기반 매칭 큐, 실시간 채팅·시간 투표,
5분 전원 수락, 참가 확정, 안전한 매치 취소, 결과 투표와 서버 ELO 반영, 도전과제·칭호,
경기 후 명예, 알림·경기 이력 동기화와 운영자 판정 기반 3회 제재가 포함됩니다.

로컬 Supabase 실행, 호스팅 프로젝트 연결, 두 브라우저 검증 방법은
[Backend MVP 가이드](docs/BACKEND_MVP.md)를 참고하세요.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 접속. 모바일 화면 비율로 설계되어 있으므로
데스크톱에서는 기기 프레임 안에 렌더링됩니다.

Android 앱 셸 실행과 APK 빌드 방법은 [모바일 앱 가이드](docs/MOBILE_APP.md)를 참고하세요.

### 네이버 지도 연동 (선택)

키가 없어도 **내장 스타일 맵**으로 모든 기능이 동작합니다. 실제 지도를 쓰려면
[네이버 클라우드 플랫폼](https://www.ncloud.com/product/applicationService/maps)에서
Maps Application을 등록하세요.

1. **API 선택** — `Dynamic Map` 하나만 체크 (Static Map, Directions, Geocoding 불필요)
2. **서비스 환경 등록** — Web 서비스 URL에 아래를 각각 `+ 추가`
   - `http://localhost:5173`
   - `http://127.0.0.1:5173`
   - 휴대폰에서 테스트하려면 `npm run dev` 실행 시 터미널에 찍히는 Network 주소도 추가
   - 끝에 슬래시나 경로를 붙이면 인증에 실패합니다
3. **발급된 Client ID를 `.env`에 입력**

```bash
cp .env.example .env
# VITE_NAVER_MAP_KEY_ID=발급받은_Client_ID
```

> **Client Secret은 넣지 마세요.** 프론트엔드 값은 브라우저에 그대로 노출됩니다.
> Client ID는 공개되어도 되는 값이고, 위에서 등록한 Web 서비스 URL이 사용 제한 역할을 합니다.

`.env`는 Vite가 시작할 때만 읽으므로 값을 넣은 뒤 개발 서버를 재시작해야 합니다.

인증 파라미터(`ncpKeyId` / `ncpClientId`)는 콘솔 발급 시기에 따라 다른데,
[VenueMap.tsx](src/components/VenueMap.tsx)가 두 방식을 순서대로 시도하고
둘 다 실패하면 내장 맵으로 되돌아갑니다. 실패 사유는 브라우저 콘솔에 출력됩니다.

## 데모 시나리오

전체 플로우가 백엔드 없이 프론트에서 시뮬레이션됩니다. 상대 플레이어는
NPC가 자동으로 참여·대화·투표·결제합니다.

1. **본인인증** — 이름/생년월일/통신사/휴대폰 입력 → 인증번호는 아무 6자리
   (데모용이며 실제 인증은 하지 않고 입력값만 저장합니다)
2. **닉네임 생성** → **관심 종목 선택** (테니스 · 배드민턴 · 탁구 · 농구)
3. **지도** — 내 위치 주변 체육관 마커. 마커를 누르면 전광판이 열립니다
   - ELO 리더보드 / 최근 경기 기록 탭
   - 오늘 남은 시간 현황
   - `이 체육관에서 매칭 시작` 버튼
   - 지도 하단의 `빠른 매칭 시작`은 가장 가까운 시설로 바로 큐를 돌립니다
4. **매칭 설정** — 종목과 경기 방식 선택
   - 농구: 3 대 3 만 지원
   - 테니스 · 배드민턴 · 탁구: 단식 1 대 1 / 복식 2 대 2
5. **큐 대기** — 내 ELO와 가까운 상대부터 순서대로 채워짐 →
   인원이 다 모이면 **알림 발송**
6. **매칭 수락** — 실제 백엔드 모드에서는 5분 안에 전원이 수락해야 진행
7. **일정 조율** — 체육관 타임테이블(08:00 ~ 18:00, 1시간 단위)을 보며 채팅.
   이미 예약된 시간은 선택 불가. 원하는 시간을 누르면 투표되고,
   **전원이 같은 시간에 투표하면 확정** → 알림
8. **더치페이 결제** — 참여자별로 `결제 대기중` / `결제 완료!` 표시.
   전원 완료 시 **예약 확정**
9. **경기 종료 알림** — 이용 시간이 끝나면 승패 확정 요청 알림
10. **승패 확정** — 이긴 팀 선택 → ELO 변동 반영 →
   상대 한 명에게 **경기 명예** 전달 → 누적 명예로 **명예 등급**(5단계) 상승

## 화면 구성

하단 탭바 5개로 구성됩니다.

| 탭 | 내용 |
| --- | --- |
| MAP | 지도, 체육관 마커, 전광판, 매칭 진입 |
| RANKING | 종목별 ELO 랭킹, 내 순위와 티어 진척도 |
| CLAN | 클랜 가입 / 클랜 랭킹 / 클랜 멤버 |
| ALERTS | 매칭·결제·경기 결과 알림 목록 |
| PROFILE | 전적, 명예 등급, 종목별 레이팅, 경기 기록 |

## 게임 시스템

**ELO** — K = 32 표준 공식. 팀 평균 레이팅으로 기대 승률을 계산합니다.
티어는 브론즈(0) · 실버(1200) · 골드(1400) · 플래티넘(1600) · 다이아(1800) · 마스터(2000).

**명예 등급** — 경기 후 상대에게 받은 명예 누적으로 5단계까지 올라갑니다. 경기당 상대 한 명에게 한 번만 보낼 수 있습니다.
새싹 플레이어(0) → 좋은 이웃(5) → 매너 플레이어(15) → 신뢰의 상징(30) → 명예의 전당(50).

## 구조

```
src/
  types.ts              도메인 타입
  lib/game.ts           ELO · 티어 · 명예 등급 · 거리 계산
  data/seed.ts          체육관 · NPC · 경기 기록 · 클랜 목데이터
  store/useApp.ts       전역 상태 + 매칭 진행 시뮬레이션
  components/
    VenueMap.tsx        네이버 지도 / 폴백 맵 + 마커 투영
    VenueSheet.tsx      체육관 바텀시트 (전광판)
    BottomNav.tsx       하단 탭바
    ToastHost.tsx       푸시 알림 배너
    ui.tsx              공용 UI 조각
  screens/              화면 단위 컴포넌트
```

상태는 `localStorage`에 저장됩니다. 프로필 화면 하단의 `데이터 초기화`로
온보딩부터 다시 시작할 수 있습니다.

## 현재 범위와 한계

Supabase를 설정하지 않은 데모 모드에서는 본인인증, 매칭 상대, 결제, 알림과 예약이
프론트에서 시뮬레이션됩니다. 백엔드 모드에서는 실제 사용자 로그인·매칭·채팅·투표·ELO가
저장되지만, 다음 기능은 아직 MVP 범위 밖입니다.

- 실제 PG 결제와 더치페이 정산
- 체육관 외부 예약 시스템 연동
- Web Push/FCM 알림
- 클랜 생성·클랜 채팅·클랜전
- 운영자 전용 신고·제재 관리 화면(판정 RPC와 3회 제재 백엔드는 구현됨)

게임 요소의 구현 우선순위는 [게임플레이 로드맵](docs/GAMEPLAY_ROADMAP.md), 경진대회용
예약·결제 범위는 [예약·결제안](docs/COMPETITION_BOOKING_PAYMENT.md)에 정리했습니다.
